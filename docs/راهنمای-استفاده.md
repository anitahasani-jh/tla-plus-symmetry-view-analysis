# راهنمای استفاده

این سند برای سه کس نوشته شده است: کسی که می‌خواهد پروژه را **اجرا** کند، کسی که می‌خواهد آن را **بفهمد**، و کسی که می‌خواهد آن را **ارائه** دهد. اگر عجله دارید، بخش ۱ و ۳ را بخوانید و بعد سراغ `docs/راهنمای-ارائه.md` بروید.

---

## ۱) پروژه در سه سطح

### یک جمله
SymView مشخصات TLA<sup>+</sup> را تحلیل می‌کند و می‌گوید آیا می‌توان با `SYMMETRY` و `VIEW` فضای حالت TLC را کوچک کرد — و اگر نتواند این را **اثبات** کند، کاهش نمی‌دهد و دلیلش را می‌نویسد.

### یک پاراگراف
مدل‌چکینگ صریح‌حالت با TLC برای سیستم‌های چندفرایندی منفجر می‌شود. TLC دو کاهش آمادهٔ `SYMMETRY` (یکی‌کردن حالت‌های هم‌ارز تحت جایگشت) و `VIEW` (نگاشت حالت به تصویر کوچک‌تر) دارد، اما هر دو فقط یک خط در فایل `.cfg` هستند و TLC هیچ بررسی‌ای روی درستی‌شان نمی‌کند. SymView یک تحلیل‌گر ایستاست که (۱) مقادیر واقعی ثابت‌ها را از خود TLC می‌گیرد، (۲) با پنج شرط S1–S5 بررسی می‌کند مشخصات تحت جایگشت هم‌تغییر است یا نه، (۳) با یک گراف تأثیر متغیرهای تاریخی را پیدا می‌کند، و (۴) یک ماژول پوششی به‌همراه پیکربندی هر بازوی آزمایش تولید می‌کند بدون آن‌که مشخصات اصلی را تغییر دهد.

### یک صفحه
مسئله: با n فرایند همسان، تعداد حالت‌ها نمایی می‌شود. دو کاهش استاندارد وجود دارد اما انتخاب نادرست آن‌ها **بی‌صدا** نقض‌ها را از دست می‌دهد: اگر یک عضو مجموعه «متمایز» شده باشد (`Counter = p1`)، یا انتخاب با `CHOOSE` انجام شود، یا مدل ویژگی زنده‌بودن بررسی کند، کاهش ناسالم است.

ایده: تصمیم سلامت را خودکار کنیم، اما محافظه‌کارانه. SymView برای هر ثابتِ مجموعه‌ای از مقدارهای مدل، پنج آزمون انجام می‌دهد؛ چهار آزمون **دقیق**اند (اندازهٔ مجموعه، ناوردایی همهٔ ثابت‌های دیگر تحت جابه‌جایی‌های مجاور، نبود ارجاع به عضو مشخص در ویژگی‌های بررسی‌شده، و حل‌شدن همهٔ ماژول‌ها) و یکی **محافظه‌کارانه** (تحلیل جریان اطلاعات که taint را از مرز تعریف‌ها، binderها و انتساب‌ها عبور می‌دهد و در برخورد با عملگر ناهم‌تغییر مثل `<`، حساب صحیح، `CHOOSE` یا `SortSeq` متوقف می‌شود). برای `VIEW` یک گراف تأثیر می‌سازد: متغیری که نه مشاهده‌پذیر است و نه به متغیر مشاهده‌پذیر یا به فعال‌بودن اکشن‌ها اثر می‌گذارد، تاریخی است و حذفش تصویر را به یک شبیه‌سازی دوسویه تبدیل می‌کند.

آنچه اندازه گرفتیم: روی ۲۸ مدل (۲۰ مدل عمومی پین‌شده + ۸ مدل آزمایشگاهی با پاسخ مرجع)، برای ۷ مدل کاهش معتبر صادر شد با میانهٔ ۷۲٪ کاهش حالت (بیشینه ۹۷٫۶٪). ۱۰۳ باگ کوچک تزریق شد، ۱۸ موردش را اجرای کاهش‌نیافته دید، و هر ۱۸ مورد در بازوهای قابل‌مقایسه دوباره دیده شد؛ هیچ اجرای تمیزی با کاهش به نقض تبدیل نشد (۰ از ۱۲). حکم ابزار روی مدل‌های آزمایشگاهی ۸ از ۸ با پاسخ مرجع یکسان بود و در ۲ از ۲ مدل، کاهش خودکار دقیقاً همان تعداد حالت پیکربندی دستی نویسنده را داد.

آنچه یاد گرفتیم: بزرگ‌ترین خطر، خطای ابزار است نه نظریه. یک نقص واقعی (F1) پیدا شد که در آن `SYMMETRY` صادر شده بود و TLC نقض ویژگی زمانی داد؛ شناساگر زنده‌بودن اصلاح شد و آزمون رگرسیون گرفت. عدد نهایی به‌عمد سخت‌گیرانه است: هر جا نتوانستیم اثبات کنیم، کاهش ندادیم.

## ۲) پیش‌نیازها و نصب

| نیاز | نسخهٔ آزمون‌شده | توضیح |
|---|---|---|
| Python | ۳٫۱۰ یا بالاتر (اینجا ۳٫۱۴) | فقط `src/` برای تحلیل؛ `pandas/matplotlib/scipy` برای جدول و شکل |
| Java | ۸ یا بالاتر (اینجا Oracle 1.8) | فقط برای TLC |
| TLC | `tools/tla2tools-1.7.1.jar` (TLC 2.16) | همراه بسته است، SHA-256 بررسی می‌شود |
| شبکه | فقط برای دریافت مخزن عمومی | بقیهٔ کارها آفلاین اجرا می‌شوند |

```bash
cd symview
bash setup.sh            # نصب وابستگی‌ها + بررسی TLC + آزمون دود
# یا اگر همه‌چیز از قبل نصب است:
bash setup.sh --offline
```

`setup.sh` در پایان پیام `setup OK` می‌دهد. اگر `java` نبود، مسیر نصب را نشان می‌دهد (روی Colab: `apt-get install -y openjdk-17-jre-headless`).

> **تلهٔ مهم:** فایل `tla2tools-1.7.1.jar` در مانیفستش نوشته است `Class-Path: CommunityModules.jar` و JVM این مسیر را **نسبت به پوشهٔ خودِ jar** حل می‌کند. اگر یک `CommunityModules.jar` جدید کنارش بگذارید، TLC با `NoClassDefFoundError: tlc2/value/impl/KSubsetValue` می‌میرد. به همین دلیل jar تنها در `tools/` است و ماژول‌های Community به‌صورت فایل `.tla` در `benchmarks/support/community/` قرار گرفته‌اند.

## ۳) اولین اجرا در پنج دقیقه

```bash
export PYTHONPATH=src
python -m symview analyze \
  --spec-dir benchmarks/lab/LabLock --module LabLock --config LabLock.cfg
```

خروجی مورد انتظار (خلاصه):

```
SYMMETRY
  [ACCEPT] Proc = {p1, p2, p3}  (group order 6)
           - Proc is used only through permutation-equivariant operators ...
  selected: Proc
VIEW
  verdict   : none
  retained  : owner, pending
applicable arms: plain, symmetry, view, both
```

سه حالت ممکن برای هر نامزد:

| برچسب | معنا | کار شما |
|---|---|---|
| `ACCEPT` | هر پنج شرط برقرار است | می‌توانید کاهش را فعال کنید |
| `REJECT` | یک شرط نقض شده و دلیل با شمارهٔ خط آمده | دلیل را بخوانید؛ معمولاً باگ مدل یا واقعیتِ مدل است |
| `UNKNOWN` | نتوانستیم اثبات کنیم (عملگر/ماژول ناشناخته) | طبق سیاست، کاهش صادر نمی‌شود |

## ۴) دموی کامل کاهش (چیزی که در کلاس نشان می‌دهید)

```bash
python -m symview report \
  --spec-dir benchmarks/lab/LabLog --module LabLog \
  --config LabLog_notype.cfg --arms plain symmetry view both
```

خروجی:

```
VIEW
  verdict   : sound
  dropped   : log
  retained  : owner, pending
  plain     verdict=ok  states=694 distinct=289
  symmetry  verdict=ok  states=130 distinct=53
  view      verdict=ok  states=49  distinct=20
  both      verdict=ok  states=19  distinct=7
```

یک کاهش ۹۷٫۶ درصدی با همان حکم `ok`. اگر پرسیدند «چرا `log` حذف شد؟» جواب: چون فقط برای بازمحاسبهٔ خودش خوانده می‌شود، هیچ guard یا invariant رفتاری آن را نمی‌خواند، و هیچ مسیری از آن به متغیر مشاهده‌پذیر یا فعال‌بودن اکشن‌ها وجود ندارد. اگر همان مدل با `LabLog.cfg` (که `INVARIANT TypeOK` دارد) اجرا شود، `log` حذف **نمی‌شود** چون invariant نوعی آن را می‌خواند — این تفاوت را در کلاس نشان دهید، بهترین لحظهٔ ارائه است.

## ۸) چطور خروجی یک مدل را تفسیر کنم؟

۱. اگر `SYMMETRY` گفت `ACCEPT` ولی بازو اجرا نشد، دنبال خط «the model checks a temporal property or assumes fairness» بگردید — یعنی زنده‌بودن مانع است.
۲. اگر `REJECT` با «an element of the set is distinguished» آمد، یعنی یک ثابت یا ویژگی، یک عضو را جدا کرده است؛ دنبال `Counter = p1` یا `owner = p1` بگردید.
۳. اگر `UNKNOWN` با «unclassified operators» آمد، یعنی عملگری در مسیر taint هست که جدول طبقه‌بندی نمی‌شناسد؛ محل دقیق در `src/symview/analysis/equivariance.py` است.
۴. اگر `UNKNOWN` با «value of constant X could not be interpreted» آمد، کاوشگر ثابت‌ها مقدار را از TLC نگرفت؛ لاگ `results/logs/*-probe.log` را ببینید.
۵. برای `VIEW` اگر `verdict: none` بود، یعنی هر متغیر یا مشاهده‌پذیر است یا به مشاهده‌پذیر اثر می‌گذارد — دلیلی برای حذف نیست، نه خطا.

## ۱۰) عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| `Could not find or load main class tlc2.TLC` | مسیر jar نسبی و پوشه عوض شده | از ریشهٔ پروژه اجرا کنید یا `--jar` مطلق بدهید |
| `NoClassDefFoundError: ...KSubsetValue` | یک `CommunityModules.jar` ناسازگار کنار tla2tools است | آن را از `tools/` بردارید |
| `Missing input TLA+ module` | نام ماژول با نام فایل یکی نیست | `--module` باید نام ماژول داخل فایل باشد |
| `Cannot find source file for module X` | ماژول پشتیبان نیست | فایل را در `benchmarks/support/` بگذارید |
| `The configuration file did not specify the initial state predicate` | `.cfg` فقط `CONSTANTS` دارد | `INIT`/`NEXT` یا `SPECIFICATION` اضافه کنید |
| تحلیل خیلی کند است | بررسی Constants روی مدل سنگین اجرا می‌شود | `--no-probe` یا `--timeout` کوچک‌تر |
| `setup.sh` روی نصب jupyter شکست می‌خورد | شبکه/PyPI | اختیاری است؛ `--offline` یا نادیده بگیرید |
| نتایج با گزارش نمی‌خواند | `numbers.json` قدیمی است | `make_tables.py` و بعد `make_report.py` |

## ۱۱) گسترش پروژه

* **افزودن مدل عمومی:** یک ردیف در `config/corpus.yaml` (مسیر، مدل‌ها، خانواده) → `fetch_public_specs.py` → `select_subset.py`. توجه: زیرمجموعه **پیش‌ثبت** است؛ افزودن مدل بعد از دیدن نتایج، نقض پروتکل است و باید در گزارش تهدیدها ذکر شود.
* **افزودن مدل آزمایشگاهی:** پوشه در `benchmarks/lab/`، مدل + پیکربندی، و یک ردیف در `ground_truth.yaml`؛ بعد `tests/test_lab_ground_truth.py`.
* **افزودن عملگر به جدول تقارن:** یک ردیف در `EQUIVARIANT_OPS` یا `NON_EQUIVARIANT_OPS` در `analysis/equivariance.py` با دلیل؛ بعد `make_tables.py` تا جدول مستندات هم به‌روز شود.
* **افزودن بازو:** `codegen.ARMS` + `config/experiment.yaml` + `pipeline.arm_plan`.

## ۱۲) قواعدی که در کل کد رعایت شده‌اند

۱. **هیچ عددی دستی نیست**: همه از `results/raw/**` با اسکریپت تولید می‌شوند.
۲. **مشخصات اصلی تغییر نمی‌کند**: کاهش‌ها فقط از طریق ماژول پوششی و پیکربندی اعمال می‌شوند.
۳. **بوجهٔ یکسان**: timeout، worker و heap برای همهٔ بازوها یکی است (`config/experiment.yaml`).
۴. **شکست هم نتیجه است**: timeout و crash ثبت و گزارش می‌شوند، پاک نمی‌شوند.
۵. **امتناع بهتر از حدس**: هر جا اثبات نباشد، حکم `UNKNOWN` و بدون کاهش.
۶. **نسخه‌ها ثبت می‌شوند**: `results/raw/environment.json`، `config/tools.yaml`، و commit در `results/raw/git.json`.
